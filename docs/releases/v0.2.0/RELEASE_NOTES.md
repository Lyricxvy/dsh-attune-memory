## 1. 主要工作内容

### 1.1 源码审计：定位系统性缺陷

对 v0.1.0 公开版做逐行审计，核心问题是一份跨层契约被五处各自手写、没有单一事实源：同一份「哪些 op、哪些参数合法」在引擎 RPC 的参数白名单、模型工具 schema、HTTP 路由、插件的写集合常量、引擎对象方法签名五处各有一份，靠人工同步，也没有一条端到端测试守住它们。由此已经产生真实故障：

1. **memory_preview 整体失效**：RPC 的参数白名单里没有 preview 键，但分发有 preview 分支、必填校验也有 preview 条目；参数校验先查白名单，对 preview 抛 KeyError，被统一错误处理捕获后返回带引号的错误名。
2. **兜底抽取通道整体死掉**：插件在写入每条候选前都先调 preview 再做 add，preview 必然失败，异常被 catch 吃掉后 add 永不执行，八条确定性句式一条都落不了库；失败只写调试日志，不计数、不进丢弃日志，属于静默失效。
3. **memory_forget(hard: true) 不可用**：写入层有 hard 参数，引擎的 forget/delete 不接收、RPC 白名单没有 hard、模型工具传 hard 被拒，四层不一致，模型无法硬删。
4. **管理页 /api/reads、/api/discarded 失效**：路由误用了未定义的 json(...) 与 q.get(...)（实际封装名是 sendJson / query），走到即 ReferenceError 变 400，诊断面板这两块一直是坏的。
5. **explicit 默认 True 且对模型不可见**：候选对象里该字段默认 True（危险默认），模型工具的 schema 里又没有这个字段；引擎整套推断处理（置信度压到 0.7、禁 always、禁自动取代）对模型写入而言是死代码。
6. **写集合跨层漂移**：RPC 侧有 tick 共 10 项，插件侧没有 tick 只有 9 项。

### 1.2 架构审查与决策

先做了一次内部架构复审（区分「已核实」与「推断」，不报喜不报忧），结论是 **B：局部重构后再开发**——产品目标未偏，读时 User Model 不落副本、三通道、写决策表等核心设计成立，不到推倒重来；但跨层契约无单一事实源已经产出三处真实故障加一条死通道，不能直接继续扩功能。

随后经外部独立评审交叉评议，形成八条定向意见：保留单一注册表方向但不夸大其覆盖面；explicit 默认 False 保留（属保守默认策略，不是真实性证明）；模型端移除 forget hard 通过；启动自检拿不到 describe 时应禁止写操作，而不是退回本地名单；关键测试进 CI；补真机验证的边界说明。评审同时明确这轮不做：版本号单源、统一包名、代理层压缩盲区修复、扩充新功能。

### 1.3 计划制定

计划经两轮修订（六项定向修订：权威关系重写、explicit 重新论证、forget hard 底层核实、接口与行为兼容的区分、验证矩阵补齐、范围纪律）。核心方案：

- **单一事实源的落点**：引擎 RPC 内一张 OPS 注册表（OpSpec{params, required, writes, handler} 四者同处声明），参数白名单、写集合、参数校验、分发与 describe 全部由它派生；新增只读 describe；插件启动时向引擎拉 describe 自检，不一致即 fail-closed。不做代码生成——插件要零构建，模型面向的描述属 JS 呈现层。
- **explicit 默认 False**：把不变量从「保证真实性」纠正为「不可逆覆盖必须 deliberate opt-in」。
- **删除 forget hard**：物理删除（不可逆、无审计）只留命令行与管理页，模型工具不再暴露假能力。
- **范围纪律**：Embedding、FTS5、自动遗忘、多用户、近义去重等一律不碰。

## 附录 A：计划书摘要（工作目标与方向）

**版本定位**：Architecture Closure Release（架构收口版）。v0.2.0 不推倒 Memory Engine、不新增功能，只做一件事：把「一份契约在六处手写」收口成「单一事实源 + 启动自检 + 端到端穿透测试」，并恢复三条已断的调用链，让它们恢复后有测试证明端到端闭合。

**要解决什么**：

1. 跨层契约没有单一事实源（五处独立表达）。
2. 三条已断的调用链：memory_preview、兜底抽取、管理页的诊断接口。
3. 一个安全不变量失守：「推断永不自动取代显式事实」因 explicit 默认 True 且对模型不可见，退化成「靠模型自觉」。
4. 可靠性边界不清：去重机制的真实保证范围被误认为比实际更宽。
5. forget hard 是假能力：模型工具暴露了 hard，却在引擎与 RPC 两层断裂。

**不解决什么**：Embedding、FTS5、Memory Graph、新的检索范式、自动遗忘、多用户、大规模形成式写入、新注入通道、与收口无关的交互功能、语义近义去重、语义级幂等、explicit 与 confidence 的解耦。

**成功标准**：

1. 任何一个 op 的契约只在引擎那一处定义。
2. 跨层漂移能被启动自检或 CI 端到端测试当场抓住。
3. 三条死链全部恢复，且各有一条穿透全链路的测试。
4. explicit 不变量端到端成立：不可逆覆盖必须 deliberate opt-in。
5. 抽取与 preview 失败进计数，静默失效归零。
6. forget 的模型工具不再暴露不可用的 hard 假能力。

## 附录 B：自我审核（未来还需解决的问题）

以下问题在 v0.2.0 收口时**未解决**，如实记录，不藏在「已完成」的结论后面。

1. **代理层压缩盲区（最大未关闭风险）**：真实桌面环境里，模型 API 代理会在请求体层折叠历史，不发会话事件，插件「听不见」压缩。常驻层已靠搬进 system prompt 免疫（ADR-019），但按轮注入的块仍会被折掉。真机回归里出现过「8 条注入在没有压缩事件的情况下消失」的现象，归入真实使用验收，暂缓。
2. **explicit 标注率待观察**：explicit 默认 False 之后，模型不主动标 explicit 的写入全部走推断路径。「模型会不会对用户明说的事实正确标注」是本改动的首要行为回归点，需要在后续真实使用中持续观察。
3. **版本号四处耦合**：`package.json` ↔ zip 名 ↔ `.audit` 目录名 ↔ git tag，回退要一起退，否则布局自检的 I9 会红。本轮接受现状，靠检查单兜底。
4. **授权会话 200 未验证**：诊断接口的真机验证只证明了 401（未授权被信任栅栏拦下），还没证明授权 GUI 会话下返回 200，需要实际打开管理页确认。
5. **抽取计数未真机累积**：四项计数的代码就位，但真机尚未观察到萃取写入数的增长（本轮以模型自写为主），真实使用期才是直接证据。
6. **推送与 Release 未完成**：自动化环境拿不到推送凭据，main 与 tag 由维护者在本地推送；CI 真实执行与 GitHub Release 也要等推送后确认。
7. **单一注册表仍有一处人工映射**：handler 把参数映射到引擎方法调用是唯一的人工点，没有编译期校验，靠参数校验加测试双保险（评审认为可接受，但不要夸大覆盖面）。

## 附录 C：其他（架构决策、测试、关键决策）

### C.1 本轮新增 ADR

**ADR-035 引擎机器契约只有一张 OPS 注册表，插件启动即自检**：引擎 RPC 里 `OpSpec{params, required, writes, handler}` 的 OPS 字典是唯一事实源（27 个 op 同处声明），参数白名单、写集合、参数校验、分发全部派生；新增只读 describe；插件首次调用前用 describe 比对写集合，不一致时写操作 fail-closed（BAD_CONFIG）、读照常。否掉的方案：维持四处分写（正是缺陷成因）、代码生成（破坏零依赖 clone 即跑）、只靠测试（只能事后发现）。

**ADR-036 推断写入默认降级，不可逆删除离开模型工具箱**：候选的 explicit 默认 False；推断路径统一压置信度 ≤0.7、always 降 contextual、不自动取代旧事实；hard 从写入层、注册表与模型工具三层删除，物理删除只剩命令行与管理页两段式。否掉的方案：保持 explicit=True（等于「模型说的一切都算用户亲口说的」）、用置信度阈值替代（模型对自己编的结论同样给 0.95）、把 hard 改写成 forget→purge 两步（只是换名字，模型仍能触发不可逆删除）。

### C.2 关键决策记录

- **forget hard**：维持「模型工具删 hard、物理删除仅命令行与管理页」，不采纳「工具层把 hard 改写成 forget→purge 两步」——那会让模型触发不可逆、无审计的物理删除。
- **启动自检 fail-closed**：三态 ok / mismatch / unavailable，只有 ok 放行写；describe 不可用即写禁用，删掉「退回本地名单」的路径（评审第四条收紧）。
- **I6 闸门调整**：布局自检的 I6 改为跳过整行注释、代码行仍严格命中（layout-guard 需要在注释里解释改名机制）；I5 隐私闸不受影响。
